# FoodFlow 权重敏感性小实验

> 说明：本文记录的是早期逐单派单仿真下的权重敏感性小实验。最新版正式仿真已经引入 softmax/MNL 选择模型、LightGBM-LTR 链路和批量匹配对照，正式指标以 `outputs/results/simulation_metrics.csv` 为准。

## 目的

`Seq-xQuAD-Tripartite` 是当前三方闭环中平台效用最高的策略。为了避免答辩时被质疑“权重只是手调公式”，这里记录一次小范围权重敏感性检查：固定同一批仿真用户请求、同一骑手随机流和同一选择模型，只调整三方重排权重与列表级覆盖权重，比较平台效用、ETA 和超时率。

## 固定设置

- 数据：当前完整 TRD processed 数据。
- 仿真：午餐高峰 8 个时间步，每步 16 个请求，`top_k=10`。
- 骑手策略：`load_aware`。
- 随机流：使用 `Seq-xQuAD-Tripartite` 对应稳定 seed。
- 评价：`platform_utility`、`avg_eta`、`timeout_rate`、`user_satisfaction`。

## 结论

当前默认候选 1 仍是这组权重中平台效用最高的组合。适度提高 ETA 权重时，效用几乎不变但平均 ETA 略升；过度提高用户权重会提升用户满意度，但超时率明显变差；降低或提高列表级覆盖权重都没有带来更好的平台效用。

因此当前报告保留默认权重：

```text
user_weight = 0.93
fairness_weight = 0.025
eta_weight = 0.03
supply_weight = 0.015
diversity_weight = 0.12
tail_weight = 0.04
```

答辩时可以表达为：权重不是为了单点指标任意调参，而是在小范围敏感性检查后选择了平台效用最高且履约指标稳定的组合。
